# Дыры: интерфейс и код

Аудит текущей ветки (август 2026). Не дублирует README. Приоритет: P0 — ломает работу на ТСД, P1 — риск данных/повторов, P2 — долг.

---

## Интерфейс

### P0. Разные вебхуки на одном сценарии перемещения

Скан штрихкода в документе идёт на один REST-токен (`ProductsDocumentMovingActivity`), склады и проведение — на другой (`CatalogDocumentMovingService`). Товар находится, спиннеры складов могут быть пустыми, «Провести» падает. На ТСД это выглядит как пустые «откуда/куда» и ошибка Bitrix.

То же расхождение: `ScanActivity` / `SgpActivity` vs сервисы документов.

### P0. Карточка перемещения на маленьком экране

`item_moving_product.xml` — `match_parent` + `PagerSnapHelper`, название 22sp без лимита строк. На ТСД часть полей/имени может обрезаться (как раньше в приходе). Приход уже в `NestedScrollView`; перемещение — нет.

### P1. Нет кнопки «Добавить» в списке прихода

Новый приход из приложения создать нельзя, только открыть черновик из Bitrix. Если оператор ждёт паритет с перемещением — сценарий обрывается на пустом или «чужом» списке.

### P1. Серая «Провести» без понятного текста на перемещении

Пока склады не загрузились, кнопка специально кликабельна и даёт алерт. Если склады есть, но не заполнены количество/разные склады — кнопка неактивна, тап молчит. На ярком экране ТСД это читается как «приложение зависло».

### P1. Подписи спиннеров складов

Нет явных лейблов «Откуда» / «Куда» на карточке. Два одинаковых поля, легко перепутать направление.

### P2. Список перемещений не сортируется

Приход — новые сверху. Перемещение отдаёт порядок Bitrix как есть. Свежий черновик может оказаться не первым.

### P2. Английские и обманчивые тексты

Часть ошибок сети всё ещё на английском (`Network or unexpected error…`). Лог «Redirecting to MainActivity» при неизвестной роли, по факту открывается снова `AuthActivity`.

### P2. Главное меню: id кнопок не совпадают с названиями

`productsButton` открывает **перемещение**, `documentButton` — **приход**. Работает, но путает при правках вёрстки.

## Код и данные

### P0. Три зашитых REST-токена, без единого клиента

Нет `BuildConfig` / одного `BitrixClient`. Смена контура — поиск по файлам. Риск снова разъехать права методов (barcode vs catalog).

### P1. PIN пишется в logcat

`AuthActivity`: `Attempting login with password: …`. На ТСД с USB-отладкой PIN кладовщика в открытом виде.

### P1. `usesCleartextTraffic=true` и `allowBackup=true`

Сессия в SharedPreferences может уехать в бэкап. HTTP разрешён глобально.

### P1. Проведение не транзакция на стороне Bitrix

Клиент научился не дублировать строки при retry. Если `element.add` прошёл частично (часть позиций без id в ответе), повтор всё ещё может добавить лишнюю трубу. Нет сверки с `catalog.document.element.list` после сбоя.

### P1. Неизвестная роль + сохранённая сессия

Сессия пишется до проверки роли. Неизвестная роль → `AuthActivity` при уже сохранённом логине → повторный редирект. Риск цикла.

### P1. Черновики только в RAM

`*DraftManager` живут, пока жив процесс. Убил приложение после скана и до «Провести» — позиции на устройстве пропали (в Bitrix их ещё нет — так задумано), оператор думает, что «товар исчез».

### P2. Мёртвый код

`ProductsDocumentMovingActivity.loadInitialData()` не вызывается (есть `loadInitialDataManager`). Два Retrofit в одной активности (свой + сервис).

### P2. Парсеры id не везде

`StoreMapper` / проведение строк используют `BitrixNumberParser`. `ProductMapper` и часть Gson-полей всё ещё `as? Double`. Снова возможны `1.0` и мимо складов в других экранах (инвентаризация, СГП).

### P2. `ScanService` с холодного старта

Сервис стартует в `Application.onCreate` всегда, в т.ч. на телефоне без сканера. На API 34+ receiver `EXPORTED` под системный broadcast — ок для ТСД, лишнее на обычном эмуляторе.

### P2. Тесты не покрывают ТСД-сценарий

Есть юниты на парсер id, merge скана, retry проведения, валидатор прихода. Нет проверки: один `catalog.document.add` при двойном тапе, POST conduct, вёрстка прихода/перемещения. `androidTest` — заглушка.

### P2. Жёсткие Bitrix-id в коде

Пароли: `iblockId 18`, свойство `71`. Приход выбора товара: `iblockId = 14`. Роли `75`/`76`. Смена портала = правки исходников.

## Что уже закрыто (не открывать заново без регресса)

- Двойной тап «Добавить» на перемещении (`InFlightGuard` + флаг в сервисе).
- Id склада `1` / `1.0` / `"1"` в `StoreMapper`.
- Скан во время загрузки документа не затирает строку.
- Ложный «Доступно: 7.87» без списка складов.
- Повтор «Провести» не шлёт заново строки с уже полученным id.
- Список прихода: новые сверху; карточка прихода скроллится.
- Проведение: POST `catalog.document.conduct`, разбор `Unknown API error`.

Старые дубли в Bitrix (`#462` и т.п.) клиент не склеивает — чистить в портале.

## Имеет смысл чинить следующим пакетом

1. Один вебхук (или явная матрица методов) для скана, складов и conduct.
2. Скролл карточки перемещения, как в приходе; подписи «Откуда/Куда».
3. Убрать PIN из логов; сессия и backup.
4. Сортировка списка перемещений как у прихода.
5. Либо кнопка создания прихода, либо явный текст «создайте черновик в Bitrix».
